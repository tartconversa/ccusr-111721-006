# 跨机构数据协作台账

本服务记录数据来源、字段含义、合作许可、数据产品及交付凭据。合作方可在本地演练不同机构和法域之间的资料流转；示例记录均为虚构，不连接真实口岸或支付系统。

需要 Python 3.10 或更新版本，不依赖第三方包。

运行项目测试：`python -m unittest discover -s tests -v`。
检查源码：`python -m compileall -q exchange`。
演练入口：`python -m exchange --database demo.db`。

领域逻辑分布在来源目录、合作许可、产品编排和交付核验中。`exchange/service.py` 组合这些操作，`exchange/db.py` 保存本地 SQLite 表结构；调用接口和现有边界可从源码及测试读取。

## 主体身份

合作机构更名、合并或分立后，台账不再直接改写历史记录里的接收方名称，而是分别记录法律主体、名称沿革和主体之间的关系：

- `identity.register` / `rename` / `add_name`：登记法律主体及其带有效区间的名称。旧名称在更名后不再解析到该主体；名称也可以在其他主体不再使用后依法转给新的主体。
- `identity.relate` / `withdraw`：记录 `merger`、`acquisition`、`split` 关系，可分层次串联，可撤回；撤回不改写撤回前的交付凭据。
- `grants.issue`：签发时把接收方名称解析为当时的法律主体，许可从此绑定主体，单纯更名不影响已签许可。
- `grants.authorize`：仅来源方可确认原许可是否沿某次合并/收购/分立延续。确认绑定用途范围和当时的身份关系路径；关系被撤回或路径改变后确认自动失效，需要重新确认。更名不能作为延续确认。
- `delivery.send`：直接许可按主体判定；继承许可要求存在仍有效的延展确认，并在交付凭据里保存实际的许可路径。
- `identity_trail(delivery_id, at=None)`：审计视图。`receipt` 保留交付当时的名称和路径；`relations` 列出相关主体的身份变动及是否被撤回；给出 `at` 时，`standing` 重新按该时点判断每一来源的许可是否仍成立。

合并或收购默认不会让承接方继承原许可：必须有来源方针对该许可、该用途、该身份关系的确认。品牌更名则由名称沿革表达，法律主体和许可都不变，两种情形不会被混为一次“改名”。
